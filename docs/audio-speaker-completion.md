# Recording and speaker review

The browser imports regular and exclusive speaker interval tracks as separately supplied evidence, scoped by source, recording key and run. Regular tracks may overlap; exclusive tracks reject overlaps. The browser does not synthesize exclusive diarization or infer missing transcript seconds.

Speaker review selects specific turns or intervals. Corrections preserve raw anonymous labels, supplied timing, other turns, actor and a change history. Recording-run corrections cannot be applied to a different recording/run. Source-only review also works for untimed interviews. Source version and canonical transcript JSON preserve the track and corrections.

RTTM import previews one recording's channel-1 SPEAKER records and binds them to the current recording after confirmation. RTTM exports include a loss report and deterministic aliases when human speaker names contain whitespace. Keep canonical JSON alongside RTTM: it retains run metadata, raw labels and correction history. Corrected SRT/VTT omit untimed/stale turns and report every omitted/rounded turn. Corrected TSV retains untimed turns with empty timing cells and preserves exact numeric seconds. Supplied subtitle overlap is preserved; players differ in displaying it.

The job contract accepts exact speaker count or minimum/maximum hints, language and batch size. Hints guide a model and do not prove actual identities. Options form part of queue idempotency and appear in results along with device/model/compute configuration. Model versions and accuracy still require verification on the connected worker.

Running jobs show actual adapter stage markers and indeterminate progress. Only completed jobs show 100%. The service bounds stdout, diagnostics, probe output and runtime, kills subprocess groups on cancellation/overflow/timeouts, and fences cancelled or stale results. Model diagnostics are not persisted into project-visible job errors. The optional speaker stage now runs once on the complete normalized recording before assigning absolute-time words from every transcription chunk against that same global track. It never stitches independent chunk speaker labels. Resource gates reject over-limit diarization with an actionable error; transcription-only jobs remain available for longer recordings. Exclusive tracks remain unavailable unless a provider supplies them.

Verification uses synthetic PCM audio, actual ffmpeg/ffprobe decoding, SQLite queue and subprocesses. No model download, real inference, diarization accuracy or transcript accuracy is represented by these tests. A private, untimed interview rehearsal also confirmed speaker correction and TSV retain missing timestamps; SRT/VTT report all unavailable cues instead of inventing timing.


## Whole-recording diarization worker

WhisperX is pinned to 3.8.0. Its upstream [`DiarizationPipeline`](https://github.com/m-bain/whisperX/blob/v3.8.0/whisperx/diarize.py) accepts a recording file and loads the complete 16 kHz float32 waveform. The worker normalizes with ffmpeg, validates exact PCM durations and part coverage, invokes that pipeline once, then assigns word/segment speaker labels only after shifting chunk timing into whole-recording seconds. Missing/null and zero-length word timing receives no invented speaker assignment or nearest-speaker fill. Regular overlapping tracks come directly from the global result. WhisperX's wrapper does not return exclusive tracks, so the worker reports them unavailable.

Configure `HF_TOKEN` and accept the model's access terms on the external worker. `DIARIZATION_MODEL` selects the configured global speaker model; the default is `pyannote/speaker-diarization-community-1`. The default `DIARIZATION_MAX_HOURS=2` and `DIARIZATION_MAX_WAVEFORM_MB=512` gate the complete float32 waveform before any model load. The waveform estimate excludes model/intermediate GPU/RAM overhead, so operators must provision and verify total resources. `TRANSCRIPTION_MAX_HOURS=12` bounds normalization disk work, and `TRANSCRIPTION_CHUNK_SECONDS=1200` bounds each transcription/alignment part. ffmpeg decodes only limit plus one second: an over-limit input fails rather than returning a truncated recording as complete.

Tests use real ffmpeg normalization/segmentation and explicitly labelled model-contract doubles. They prove the adapter calls one diarizer on the complete recording, reuses global labels across more than two chunks, preserves missing timing and respects resource gates. They do not prove real model loading, diarization quality, GPU resource sufficiency or transcription accuracy; those require a configured worker and separately authorized audio.

## Applying local anonymous voice estimates

`source.diarization.apply` attaches an acoustic run to the existing source revision, recording key and source recording hash. It requires a decision for every existing timed ASR segment, retains original text, timing and raw labels, and preserves previous source snapshots. Mixed, short and low-coverage segments can remain Unassigned. Single-voice clustering intervals cannot be used to claim overlap detection or supplied exclusive tracks.

The Speaker review view distinguishes machine estimates, unresolved segments and researcher-recorded corrections. Relative dominance and coverage are acoustic heuristics, not calibrated correctness probabilities. Playback, surrounding segment context and notes support selected corrections; a recorded label does not independently verify a person's identity. Textual prompts, rhetorical questions and quoted speech should be reviewed separately from voice separation. Anonymous labels apply only within their recording.

Immutable application inputs permit safe retries without restoring machine estimates over subsequent researcher corrections. A new automatic run cannot overwrite recorded researcher speaker decisions. Native project and transcript JSON retain the estimated run, assignment diagnostics and label history. Source wording, coding and analytical chart decisions are separate from speaker proposals.

Local clustering can use publicly available speaker embeddings and voice activity detection when a gated diarization model is unavailable. Such output remains a machine draft requiring audio review. Downloading public model weights does not require sending the interview audio to an external provider. Model provenance and diagnostics must identify the actual inference, limits and candidate cluster counts; synthetic integration tests do not establish accuracy on interview recordings.
