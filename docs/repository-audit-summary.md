# Repository comparison and implemented workflow

Eight dedicated agents inspected one pinned upstream repository each. Their reports are source-grounded feature samples, not exhaustive parity certification. A subsequent six-agent implementation pass and independent browser/security reviews completed the principal implementable workflow gaps below. The original individual reports record the earlier findings; this summary and the in-app Feature audit describe current implementation.

| Reference | Audit | Current implementation | Verification boundary |
| --- | --- | --- | --- |
| AQDA | [Pinned comparison](repository-audits/aqda.md) | Hierarchies/memos; paragraph semantic chunks; example-seeded all-source suggestions; context budgets; adaptive outliers; named code sets; safe memo references; native SQLite import | Actual upstream schema fixture imported. No configured language/embedding model; native outward exchange uses REFI rather than AQDA snapshots. |
| Taguette | [Pinned comparison](repository-audits/taguette.md) | Exact text coding; previewed CSV codebooks; HTML/ODT/EPUB/RTF/encoding/paste imports; RTL; roles/presets; native SQLite import | Actual upstream ORM/highlight extractor fixture imported with exact UTF8 byte-to-codepoint bounds. Shared highlight authors remain unidentified; credentials/permissions are excluded. |
| QualCoder | [Pinned comparison](repository-audits/qualcoder.md) | Text/image/PDF/media coding; typed cases/attributes; reports; code portraits; weighted hierarchy; concept maps; independent text/media/region comparisons; CSV/XLSX/ODT and REFI exchange | Actual pinned PyQt importer exercised with synthetic QDC, text, annotations, media and PDF exports. | pyannote.audio | [Pinned comparison](repository-audits/pyannote.md) | Recording/source/run-bound regular and separately supplied exclusive tracks; overlap display; selected speaker corrections; hints; RTTM and corrected subtitle exports | Canonical track/roundtrip tests pass. Wrapper does not invent an exclusive track; model access/terms and inference quality remain unverified. |

Real English OCR runs in the browser using locally hosted Tesseract worker, WebAssembly and trained data. Recognition remains unreviewed until corrected. Its explicit limits are 16 MiB, 12 megapixels and 12 PDF pages. It requires no external processing service.

Private interviews and histories stay in the owner-private app. GitHub contains synthetic seeds, source and public-safe tests only. The GitHub Pages workflow builds a browser-local synthetic demo; it does not provide shared D1/R2 state, authenticated collaboration or hosted model inference.

See [completion verification](completion-verification.md), [audio contract](audio-speaker-completion.md) and [team isolation](team-permissions-and-blind-coding.md) for acceptance evidence and practical limits. Application source was independently implemented; upstream applications were inspected/tested as references, not vendored as application code.

A subsequent [public example import audit](public-sample-import-audit.md) exercised actual committed educational projects, populated RQDA data and upstream-generated examples. It added native Requal, exact SQLite text decoding, speech table formats and explicit case-table mapping, with sample-specific verification limits.
