## Qualitative-analysis method and review

The new Framework Method workbench records a research question, working themes and explicit familiarization, coding, framework application, charting, interpretation and critical-review stages. Its matrix charts each source recording against each theme. Source rows are not asserted to be verified participant identities.

Each chart cell stores an attributed working summary, qualifications/negative cases and exact supporting or contrasting citations. Observed, not observed within reviewed scope and withheld are distinct states. Missing charts do not become absence claims. Prior interpretations and review reasoning are retained. Source edits or new restrictions make evidence ineligible for review/reporting until current quotations are selected again. CSV and readable HTML exports retain these boundaries.

Analyst and critical-review subagents can rehearse the researcher review loop by proposing interpretations and checking exact source anchors, contradictions and unsupported claims. Agent review is explicitly recorded as agent review; it does not substitute for participant consent, researcher judgment, verified transcription, saturation or independent human intercoder reliability. The actual interview analysis and its private review ledger are kept outside Git.

New normalized coverage reports measure union-covered eligible codepoints, and separately saved applications per 1,000 eligible codepoints. Consent restrictions and current case-passage scope affect the denominator. Parent codes/cases may overlap and are nonadditive. The coder heatmap preserves code/source dimensions; relationship drilldowns keep text codepoints distinct from recording seconds. Counts and visualizations describe the selected evidence and decisions rather than thematic prevalence or causal effects.

## Consent scopes and source review

The source-review screen detects candidate off-record/nonattribution phrases for researcher review, supports exact passage scopes, and records pending, included or withheld decisions with authorization reasoning, reviewer attribution and prior history. Phrase detection does not establish where a recording returns on record or automatically authorize inclusion.

Included current scopes can enter analytical evidence; pending/withheld scopes stay excluded. Editing across an included scope suspends its authorization until re-anchored and reviewed. The transcript probability view exposes native ASR probability semantics separately from alignment scores and excludes stale anchors. Neither feature establishes transcription accuracy or speaker identity.

Readable annotated-source reports replace restricted text and omit intersecting coding quotations, private notes, review rationales, source versions and arbitrary attributes. Consent controls govern analytic eligibility; they do not erase original data. Native project archives intentionally preserve original source text and available history, including restricted passages, and are not anonymized/redacted sharing packages.

## Project archives and file formats

The native project ZIP can include original current and historical recordings/images/PDFs, or contain transcripts and project metadata only. It preserves native source/coding/review/memo/case/framework/consent state, transcript timing, source revisions and available server metadata, with integrity checks and an explicit availability manifest. Import remaps uploaded media references without silently replacing prior recordings; transcript-only imports keep media references as provenance and disable unavailable playback.

Server membership, audit history, processing jobs and recovery indexes are reference records when supplied, not recreated access grants or restarted jobs. Private account notes, service credentials and model/embedding caches are excluded. Browser ZIP assembly/import remains memory-based; original recordings can require substantial memory. REFI-QDA standard XML represents a reduced interoperable subset while native sidecars retain additional workflow/timing history; receiving-app behavior still needs verification. See [export-format guide](export-formats.md) and [annotated-report details](feature-gaps-team-import.md).
