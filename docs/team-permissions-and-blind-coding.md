# Team permissions and blind independent coding

The owner controls a revisioned project policy in the Team screen. Role capability switches cover coding, codebook editing, shared sources, study structure, notes and journals, AI/search services, recording jobs, decision history, and recovery downloads. Standard, manual research, and focused coding presets provide starting points. Existing projects keep their current permissions until the owner saves a policy. A permission limits existing role authority; it does not turn a coder into a reviewer or a viewer into an editor.

With blind coding enabled, coders receive only their own coding applications, shared notes, journals, suggestions, personal reading records and pending tasks. Other researchers' decisions, consensus, query snapshots, code-definition review histories, and imported legacy analysis records are omitted. Shared source text, supplied turn timestamps, code definitions, source/case attributes and whole-source case structure remain available. Owners and reviewers retain the complete project for comparison and adjudication. Viewers retain their read-only observation role.

The Worker enforces the policy using the authenticated identity and membership role. Request bodies cannot select an actor or role. Operations apply to the complete server state with a revision check, so saving from a filtered coder view cannot overwrite other researchers' decisions. State responses and native/REFI client exports use the same projection; AI reviews receive that projection. Exact and semantic source search can still search shared eligible source text. Blind history uses the authenticated actor's audit rows. Historical recovery downloads, shared source changes and recording processing are blocked for blind coders. Restoring a recovery point preserves the current permission policy, so an older snapshot cannot silently disable blind coding.

Private account notes remain in their separate author/project table, outside shared state, audit history, backups and AI evidence. The notes permission controls new private-note writes; authors can still read their existing notes after a permission change.

Imported coder labels are historical attribution, not authenticated identities. The application does not infer that an imported name or email belongs to the signed-in researcher. Blind coders see decisions created under their authenticated user ID; owners/reviewers can inspect historical imported attribution. An explicit owner-reviewed imported-identity linking workflow remains a separate interoperability requirement.

Previously viewed or downloaded data cannot be recalled. Enable blindness before independent coding begins. Permission changes take effect on the next server request; refresh the browser to replace an earlier view. This policy does not implement encrypted per-coder projects, realtime presence, or source-level access restrictions. Source/case attributes and shared code definitions should contain common study metadata rather than adjudication notes.

Verification covers authenticated Worker requests, stale revisions, forged actor/role bodies, hidden record IDs, AI evidence filtering, both history endpoints, recovery/download and upload/job denial, private-note separation, permission escalation rejection, native QDPX sidecars and standard XML, and current-policy preservation on restore. A private interview rehearsal preserved all 302 source turns and their supplied timing while one independent coding application was added; the coder export contained that one application and retained the source timing.
