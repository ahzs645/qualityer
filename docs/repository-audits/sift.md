## Feasible work ranked

1. **Correct typed query relations immediately.** Current runtime reproduction falsely combines distinct recordings because generic text anchors coincide. Proposal helper and three passing focused tests are in `query-kind-guards.mjs` and `query-kind-guards.test.mjs`; integration instructions in `query-kind-guards-integration.md`. Preserve whole-application semantics and label units/unsupported region queries. Add queryCodings-level tests before integrating.
2. **Correct word-scope source-attribute filtering.** The Workbench coding scope uses `matchesAttribute` (numeric/date operators), but its `docs` vocabulary scope uses string equality and ignores selected `attributeOperator`. A Score>=5 filter can therefore show correct coding with words from only Score==5 sources. Extract a shared source-scope function; test >=,!=,date and0/false before adding new visuals. Do not silently apply code filters to whole-source vocabulary.
3. **Expose explicit word analysis controls and source/code scope.** Start with minimum letters/skip verified speaker prefixes and source-incidence column, with exact Unicode tests; then an explicit coded-passage mode that unions overlaps. Built-in Hindi list should have sourced/licensed test coverage, not invented stopwords. Cloud rendering is lower priority than transparent counting.

Full interval queries and node-link maps are valuable next increments but require dedicated specifications and runtime evidence. Do not mark them implemented because Boolean dropdowns or connection cards exist.
