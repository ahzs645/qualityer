## Security/verification limitations found in actual source

- **OpenQDA is not evidence for granular reviewer/coder permission parity:** currently configured role is admin, and most QDA authorization policies are membership-based. Features must be assessed by actual controller/request policies, not framework role declarations alone.
- **OpenQDA presence/navigation is partly dormant:** Echo/presence channel code exists, but the client navigation POST and controller broadcast are commented out. No runtime collaboration claim can be made from those files.
- **Potential upstream private-note audit exposure:** `Note` uses the Auditable trait, `AuditService.collectProjectAudits` gathers every project note's audits and excludes only ID/project/author fields, while `AuditsController` authorizes project viewing rather than per-note visibility. This is a source-level risk, not a reproduced exploit. Do not copy that path into our app. Our private-note table is intentionally excluded from shared events.
- **Our identity boundary depends on hosting:** trusting injected identity headers is correct only behind the configured authenticated proxy. A generic serverless deploy requires that same trust boundary. `LOCAL_DEV` mocks are not authentication.
- **No upstream runtime exchange/service test performed.** Exact commit links establish source evidence, not a successful hands-on import/transcription/presence run.

## Three feasible improvements ranked for implementation

1. **Extend existing source sequence with ordered multi-source code portraits** (small/medium, high visualization value). `CodingSequence` already handles source-position heatmaps; the added view would compare multiple sources by colored application/excerpt tiles. Build a pure portrait-layout helper from `scopedCodings`; place one tile per declared unit, use stable source-position ordering, integrate existing quotation drilldown and SVG export. Acceptance: overlaps, Unicode, repeated coder applications, stale-anchor/consent exclusions and scoped export agree with evidence tables. Avoid interpreting tile density as prevalence or duration.
2. **Add structured audit diffs plus target/text filtering** (medium, strong team value). Introduce a server-side safe operation-diff adapter and model/target IDs at write time, then show concise before/after fields in `TeamHistory`. Never diff/import private-note or service-secret contents into shared events. Acceptance: source revisions, code rename/archive/restore, role changes and consensus display old/new attribution; denied writes create no successful event; recover deleted target names without leaking private text.
3. **Add reusable named codebook sets/template preview** (medium, improves repeated studies). Start with local/file templates and per-project activation rather than a public discovery service. Preserve collections, stable source IDs, definitions, ordering and noncodable categories; preview collisions/remapping before import; explicit export excludes interviews and quotation-linked memos. Acceptance: two books with identical code names remain distinct, toggles preserve existing coding, and synthetic QDC roundtrip reports category losses.

Live presence is a separate medium/large service project, not a quick UI addition. Full disaster recovery is operational work, not equivalent to project snapshots. These remain material priorities for a small research team but need deployment-level rehearsals.
