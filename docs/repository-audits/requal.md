## Concrete mismatch reproduced

Our current comparison path ignores the eligible-evidence scope used by AnalysisWorkbench. With a synthetic ten-character document, a consent-review flag `[0,5)` and matching coding by two coders on `[0,5)`, `scopedCodings` returns **0** eligible applications, but `agreement` reports **100%** and `characterKappa` reports **1** over **10** codepoints. This was executed locally (**W-R**), using synthetic alphabet text only. `Comparison` also renders those coding quotations in its disagreement table. Reference sources and stale sourceRevision checks similarly need shared eligibility handling.

This is an analysis-consistency issue, not proof of exposure to nonmembers: current project members already receive shared project state. Fixing it must not be presented as blind-coding authorization.

## Ranked feasible work

1. **Scoped agreement + interval-union Jaccard.** High value, low-to-medium implementation cost. Reuse a single eligibility model for exact agreement, comparisons and kappa; remove reference/consent-review characters from kappa's denominator; exclude stale/removed/media anchors; add per-code and all-pair rows with export. Preserve human coder records and genuine zero coordinates. An independently written proposal and **seven passing synthetic tests** are available in `requal-comparison.mjs` and `requal-comparison.test.mjs` beside this report. These scratch files are not yet integrated into the app. Neither Requal R code nor private interview content was copied.
2. **Explicit text-encoding preview.** High practical value for mixed historical research files, low-to-medium cost. Add UTF-8/UTF-16LE/UTF-16BE/Windows-1252 choices for TXT/MD/CSV and a replacement-character warning; preview before import. Accept a strict selected decoder, retain origin encoding as import metadata, and anchor only the final confirmed decoded text. Never reinterpret an existing source silently.
3. **CSV codebook mapping and collision preview.** Medium value, modest cost. Add the format used by Requal (as an adapter, not a claim of identical native project exchange); choose column→name/definition/color/category, validate duplicates, preview new/changed/skipped rows, require explicit rename/update collision handling. This also benefits Taguette-style CSV migration.

Blind-coding isolation and 18-switch permission parity are substantial server/data-model changes, not quick UI additions. They should be designed with read projection, export/recovery policy, reveal stages and multi-account tests before any claim of completion. Researcher attributes, native RQDA migration, Requal-specific segment overlap and real-time collaboration still need separate work.

## Acceptance tests for those changes

- Agreement fixture: coder A `[0,10)`, coder B `[5,10)` → exact-span agreement 0%; interval-union Jaccard 0.5. Include duplicate/overlapping decisions for A and verify the union remains 10. Same coordinates in different sources or codes must never overlap.
- Eligibility fixture: reference sources removed; consent-review `[0,5)` removed from the character denominator; coding crossing it fully withheld; malformed consent boundaries fail closed; invalid/source-revision-mismatched anchors withheld; untouched valid legacy exact anchors remain usable.
- Unicode fixture: `😀éabc` has five codepoints, coding `[0,2)` covers the emoji and accent; two identical decisions yield Jaccard/kappa 1. Empty coded union → undefined Jaccard; all uncoded/constant binary corpus → undefined kappa, not 0 or 1. Distinct coder validation required.
- Scope/export fixture: selected source/code/status matches all displayed counts, disagreement rows and exported rows; pairwise roster produces each unordered pair once; CSV contains counts, numerator/denominator, corpus scope and method, without raw quotation text.
- Encoding fixture: known UTF-16LE/BE with BOM, Windows-1252 smart quotes and valid UTF-8 accents preview the intended text; incompatible encodings report failure/corruption before save; cancel leaves project unchanged; speaker JSON/SRT/VTT timestamps remain unchanged by this feature.
- Codebook fixture: commas/newlines in definitions; duplicate/collision names; invalid color; missing name; categories sharing a code label. Preview identifies every conflict, cancel writes nothing, confirmed operations are attributed and preserve existing coding IDs/links.
- Future blind access fixture: a coder cannot obtain another coder's decisions via GET project, events, backup download, export, AI/semantic responses or media-derived jobs; reviewers see the intended stage only; reveal and revocation produce audit events; compare is disabled until the allowed reveal stage.
