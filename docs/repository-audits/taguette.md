## Three practical gaps to implement now

1. **Codebook CSV preview/import/export.** A dependency-free proposal and eight synthetic tests are in `proposals/codebook-csv.mjs` and `proposals/codebook-csv.test.mjs`. Preview rows must be validated before mutation, selected with required ancestors, and committed in one revision-guarded operation. Test Taguette-shaped CSV with Unicode, commas, embedded newlines, BOM, duplicate conflicting descriptions and existing ancestors. Never infer hierarchy from slash-delimited names without an explicit choice: Taguette itself treats paths as literal names.
2. **Keyboard-safe modal behavior.** Improve the shared modal once to cover all workflows: initial focus, Tab/Shift+Tab cycling, Escape, returning focus to trigger, and background inertness. Browser acceptance needs nested overlays, validation error focus, saving-state handling, keyboard-only open/select/save/close, and a screen-reader name. This is an infrastructure change with broad value.
3. **Document direction setting.** Persist auto/ltr/rtl source metadata and apply it to source text and exported report text without applying it to unrelated controls. Synthetic mixed-direction browser acceptance must verify selection anchors, correction behavior and byte/codepoint exports remain accurate. Native converters are a larger separate work item.

- Taguette uses flat tag names with prefix retrieval; our actual code/category hierarchy is richer, but mapping path names to tree nodes is an explicit transformation.
- Taguette CSV codebook import is missing at the baseline despite existing generic coding CSV export.
- Our tested scoped XLSX, ODT, reports, attribute and chart features exist. Describing the app as lacking all reports/visualizations is stale.
- Our automatic version snapshots already exist. Per-operation recovery does not establish scheduled off-site backup parity.

## Integration notes for proposed module

- `previewCodebookCSV(text, state, {separator:null})` returns `{entries,errors,warnings,codes,separator}`. Existing matches are retained, not overwritten. A selected separator produces parent-first temporary IDs and non-codable inferred ancestors; definitions explicitly present in CSV stay codable.
- `exportCodebookCSV(state, {separator:'/',spreadsheetSafe:false})` writes Taguette-compatible columns. A separator already contained in a code name is rejected to prevent ambiguous structural export; allow users to choose another separator or literal flat export if needed.
- Spreadsheet formula neutralization is opt-in because prefixing apostrophes changes exact code names/descriptions. A safe spreadsheet copy and an exact interchange copy should be distinct choices.
- Current `src/app.jsx:78` codebook import loops separate network mutations. A mid-import failure can leave a partial codebook. Parent integration should add an atomic import operation which verifies errors/duplicate paths and maps temporary parent IDs on the server. Render previews with ordinary React text nodes.
- `node --test /workspace/scratch/repo-audits/proposals/codebook-csv.test.mjs` passed 8/8 in this audit. A running Taguette import test is still required before advertising external app verification.
