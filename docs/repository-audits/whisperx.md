# WhisperX audit against Research Weave

Audited 2026-10-03. Upstream snapshot: `m-bain/whisperx` commit `771b4a14a9486f8fd5aef18ef49e35d639523dd3`, whose pyproject declares `3.8.7rc1`. Research Weave baseline: `36853ffe4f238a85b94ef2a705f2d8aa69feb707`. Local source was inspected; no application files, deployment, connection settings or GitHub branch were changed by this audit. This report uses only public upstream evidence and synthetic checks.

## Verdict

Research Weave has a real WhisperX integration implementation, a separately hosted durable recording service, timestamp-preserving imports and human review. It does not yet have verified WhisperX execution or quality, nor the complete upstream configuration/output interface. The relevant service folder is `services/transcription`, rather than `services/audio-worker`.

The distinction matters: passing authenticated queue, retention, cancellation and timestamp-import tests demonstrates the integration contract. It does not demonstrate that a model loads on the target host, that a generated word timestamp matches speech, that diarization identifies speakers consistently, or that a multi-hour recording finishes with acceptable resources.

## Verification performed

`python -m unittest discover -s services/transcription -p 'test_*.py' -v` passed **12 checks**. These cover authenticated production ASGI upload with real ffprobe, idempotency, project isolation and cancellation; durable queue restart; concurrent single claim; retry/backoff; lease recovery and stale-result fencing; running process cancellation; input/result retention; and actual ffmpeg normalization of a short synthetic WAV. The queue fixtures explicitly identify their output as queue/media-decoding checks rather than generated speech.

`node --test tests/timestamp-history.test.mjs` passed **5 checks**. These verify zero versus missing timestamps, fractional seconds, words/raw provenance, native JSON/QDPX timestamp history, speaker corrections, wrong-recording seek prevention and review requirements after source/media edits.

No WhisperX, wav2vec2 or pyannote model was installed or invoked. No Docker image build or GPU test was performed. Upstream quality/speed claims in its README remain upstream claims. Also note upstream README limitations differ from newer interpolation tests; unknown-word timing behavior must be verified against the exact deployed release rather than assumed from the README.

## Work that can be completed now

1. **Fix language-aware alignment and provenance.** Reinitialize or cache alignment models by actual detected language per chunk; keep segment/chunk language and a `mixed` result language where applicable. Add a language override only with validated service configuration. Synthetic adapter-contract tests should force `en → fr`, assert both alignment loaders are called and check exact offsets. This proves orchestration, not bilingual transcription quality.
2. **Validate completed worker transcripts before storing them.** `queue_store.py:complete` requires only a dictionary with a segments array and `server/audio-jobs.mjs` checks only that array exists. Reject non-object turns, non-string text, nonfinite/negative/reversed seconds and malformed words. Keep legitimate missing word timing and zero intact. Independently validate server-side results from any connected worker. Do not require no overlaps: real diarized speech can overlap.
3. **Bound subprocess output while reading it.** `execute_subprocess` calls `communicate()` and checks the 4 MB cap only after collecting stdout; stderr is also accumulated without a bound. Use bounded file/stream collection, sanitized truncated stderr and process termination at the limit; size limits should apply before memory grows. Add a noisy child-process test and verify cancellation/lease fencing still work.
4. **Expose honest stages and capabilities.** Replace fake-looking 0% progress with queued/decoding/chunk N of M/alignment/diarization stages, measured progress where available and unknown otherwise. Add worker capability metadata for global diarization and tested engines/models. Show the multi-part diarization limit before expensive submission when known duration/capability information is available.
5. **Export corrected timed transcripts.** Implement SRT/VTT and millisecond TSV as separate modules; omit/report untimed turns instead of inventing seconds. Preserve Unicode, zero, fractional seconds and speaker labels. Add synthetic round trips with overlapping cues and missing times. Keep native JSON as the lossless exchange format.
6. **Harden job acknowledgement and cleanup.** Cancellation response should reflect actual terminal state rather than always saying cancelled. ffprobe timeout should terminate/reap its process. Avoid replacing an existing job's input if a supplied UUID already exists in another project. Add direct gateway contract checks using synthetic WAVs.

## Work requiring an actual audio host/model verification

- Pin and build the CPU container, verify model downloads/caches and perform ASR/alignment on consented or public speech. `/health` currently reports configuration/queue readiness rather than successfully loaded models.
- Test 19:59/20:01 boundaries and multi-hour recordings, memory, temporary disk, output size, cancellation at decode/inference, worker restart and retry budget. A transcript can exceed the current 4 MB result cap independently of recording byte size.
- Verify whole-recording speaker clustering before lifting the explicit multi-part diarization restriction. Adjacent chunks using `SPEAKER_00` is insufficient evidence of identity.
- Evaluate ASR word errors, proper names, numbers, bilingual detection, alignment error, overlap and diarization on an approved evaluation set; record exact model revisions and tolerances. Queue success must remain separate from transcript accuracy and human speaker verification.

## Recommended next slice

Do language-aware alignment, transcript boundary validation, bounded subprocess handling and honest capabilities/progress first. They are small, independently testable reliability improvements that protect future timestamp/audio linkage. Subtitle export is a useful interface addition. Treat global diarization and model-quality claims as a separate host-backed milestone.

## Tested scratch proposal

`/workspace/scratch/repo-audits/whisperx-proposal.patch` proposes language-aware alignment selection and result validation at both Python queue completion and Site ingestion. The standalone implementation is under `/workspace/scratch/whisperx-proposal`. It preserves null/missing/zero/fractional values and overlapping segments, validates timing alias precedence used by transcript import, rejects malformed segments/words and never fills timing. Patch applicability was checked with `git apply --check` against the baseline; it was not applied to the app by this audit.

Scratch verification: **17 Python tests passed** (12 existing + 5 new orchestration/queue/validation checks), **3 JavaScript result-boundary tests passed**, and the proposed server route passed `node --check`. Alignment selection uses a mock model-loader contract explicitly; no generated speech or model quality is claimed. Bounded output, progress and mixed-language provenance are subsequent work, outside this small patch.
