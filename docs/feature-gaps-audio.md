## Validation

`python -m unittest discover -s services/transcription -p 'test_*.py' -v`: 34 passing checks, including backend capability reporting and rejection before upload, exact native timing/confidence preservation, full-recording normalization, global speaker assignment contracts, resource limits, stage signals, cancellation, retries, project scope, idempotency and retention. These contract tests do not measure model accuracy.

`node --test tests/transcript-quality.test.mjs tests/audio-job-rejection.test.mjs`: four passing behavior checks for probability semantics, histogram bounds, missing evidence, zero seconds, threshold filtering, stale transcript revisions and durable job acknowledgement recovery. The submission regressions use the real SQL migrations and database engine: worker HTTP 400/401/403/413/415/422 fail immediately with actionable status reasons; 429/5xx, network interruption and malformed acknowledgements retain reconciliation. Upstream diagnostic bodies are not exposed.

Runtime interview validation completed both supplied original recordings (M4A and QTA) through an actual localhost FastAPI HTTP gateway and its durable subprocess worker, with cached `base.en` CTranslate2 model, faster-whisper 1.2.1, CPU int8, native word timestamps, beam 5 and no diarization.
