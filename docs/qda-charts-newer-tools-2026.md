# Charts and visuals in newer qualitative / research / AI analysis tools

Researched November 2026 from vendor help centres, changelogs and practitioner write-ups. Where only marketing pages or third-party reviews exist, the row says so. Features I could not find documented are left out or listed under "Not documented".

**Small-n fit key.** *Good*: works with 4–30 participants. *Caution*: useful, but the default count is passages, so it shows who talked most rather than how many people. *Poor*: the chart implies prevalence or volume, or it needs hundreds of responses.

**Units.** "Passages" means highlights, notes, excerpts, observations or quotations. "Participants" and "sessions" are de-duplicated counts.

## Most interesting ideas for a small-n framework study (ranked)

1. **A participant × code matrix as the home view** (CoLoop grid, rainbow spreadsheet, ATLAS.ti code-document table). Use one column per participant and one row per substantive code. Fill each cell with presence plus the **dominant stance colour**, mark the strongest evidence grade with a glyph or border, and let a click open the passages. This is the framework-method chart with modern drill-down.
2. **Count participants by default, with a unit toggle** (Condens Highlights/Sessions/Participants, dscout "Show Count By", Dovetail "Notes by tag"). Show "3 of 4 participants" next to any passage count. Label passage counts plainly as passage counts, so nobody reads them as prevalence.
3. **An overview row or column with participant counts and the n shown** (CoLoop overview row). Summarise each code as "n participants" plus a stance distribution bar. Avoid percentages while n < 10.
4. **Stance as a spectrum per code** (Cooper variable scales, Evergreen spectrum display). One horizontal S1–S5 scale per code, with each participant as a labelled dot, shaped or shaded by evidence grade. This shows disagreement directly and is the most novel fit for coded stance.
5. **Group the columns by attribute** (Notably's segment option, CoLoop "Show as column", EnjoyHQ breakdowns, Dedoose Code × Descriptor). Order the participant columns by role level or organisation type with header bands, so differences between groups show up without any statistics.
6. **A co-occurrence chord or matrix with a strength index** (Reframer and Marvin chord diagrams, ATLAS.ti c-coefficient). Count co-occurrence within passages or within participants. A c-coefficient-style normalisation helps keep frequent codes from dominating.
7. **Dot quote explorer** (Pew). One dot per participant (or per passage, coloured by participant). Selecting a code lights up the people who raised it and lists their quotes, filterable by stance and evidence grade. Honest at small n, because every mark is a real person.
8. **Observed vs expected marker for each attribute group** (Kapiche). For each code, show each group's share of participants, with a tick marking that group's share of the whole sample. Present it descriptively and leave out significance flags (unlike Thematic) until n is about 30.
9. **A stacked sentiment ring or bar showing stance mix per code** (Qualtrics bubble ring, Medallia sentiment by topic). Use bar length = participants, not passages.
10. **Normalise for talkativeness** (ATLAS.ti document-length normalisation). If passage counts are shown at all, offer "per 1,000 words" or "share of this participant's passages".
11. **Harvey balls in the matrix cells** (Evergreen chooser). A compact, ordinal way to show evidence strength E1–E4 per participant and code. They read better than numbers when printed in a report.
12. **A session timeline with markers** (dscout scrub-bar moments). Coded passages placed along each interview's timeline show where in the guide each code and stance came up.
